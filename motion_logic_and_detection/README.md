# Motion Logic and Object Detection

Данная директория содержит программную часть проекта, отвечающую за **обнаружение объектов и автономное управление квадроподом Aliengo** в симуляционной среде.

Система объединяет:

* управление роботом через ROS 2;
* получение RGB и Depth изображений;
* обнаружение объектов с помощью YOLO;
* дополнительную проверку обнаружений с помощью ORB;
* оценку расстояния до объектов по Depth-камере;
* обход препятствий;
* последовательный поиск и достижение заданных объектов;
* передачу данных между ROS 2 и симулятором Isaac Gym;
* запись положения робота и результатов работы в лог.

## `assets/`

В каталоге `assets` находятся изображения объектов, используемые при подготовке модели YOLO.

Целевые классы проекта:

```text
cup
laptop
bottle
chair
backpack
```

Изображения также используются во время работы программы как **эталонные изображения для ORB matching**. Детектор загружает изображения соответствующих классов из `assets`, извлекает из них ORB-признаки и использует их для дополнительного сопоставления с обнаруженными объектами.



ORB ищет файлы, соответствующие имени класса, например `cup.jpg`, `laptop.png` и т. д. Поддерживаются форматы `.jpg`, `.jpeg`, `.png`, `.bmp` и `.webp`.

> Само обучение YOLO в данной директории не выполняется. `detector.py` использует уже обученную модель `.pt`.

## `cv/detector.py`

`detector.py` — основной модуль компьютерного зрения.

Он реализует класс `ObjectDetector`, который получает RGB- и Depth-изображения и возвращает информацию об обнаруженных объектах. На выходе формируется объект `Detection`, содержащий класс объекта, confidence, bounding box, расстояние до объекта и его 3D-положение в системе координат камеры.

### YOLO

YOLO является основным методом обнаружения.

Используются следующие классы:

```text
cup       → 0
laptop    → 1
bottle    → 2
chair     → 3
backpack  → 4
```

Модель загружается из `yolo26m.pt`. 

### ORB verification

После обнаружения объекта YOLO его bounding box может быть дополнительно проверен с помощью ORB.


Для сопоставления используются ORB-дескрипторы и `BFMatcher` с Hamming distance. Для фильтрации совпадений применяется Lowe's ratio test.

### ORB fallback

Если YOLO не обнаружил объект, ORB может использоваться как дополнительный метод поиска.

Это позволяет получить обнаружение даже в ситуации, когда YOLO не сформировал подходящий bounding box.

### Depth и 3D-положение

После обнаружения объекта из Depth-изображения берётся глубина в небольшой области около центра bounding box.

Затем пиксель с известной глубиной преобразуется в 3D-координаты:

```text
pixel + depth
      │
      ▼
[x, y, z] в системе координат камеры
```

Для этого используются внутренние параметры камеры `fx`, `fy`, `cx`, `cy`.

Объект считается достигнутым, когда расстояние до него не превышает:

```text
0.5 м
```

### Результат детектора

Каждое обнаружение представляется структурой `Detection`:

```text
label
object_id
confidence
bbox
distance_m
xyz_camera
source
yolo_confidence
orb_score
```

Поле `source` позволяет определить, каким способом было получено обнаружение:

```text
yolo
yolo+orb
orb_corrected
orb
```

## `controller.py`

`controller.py` — основной ROS 2-контроллер автономного поведения робота.

Он получает данные от сенсоров, передаёт изображения в `ObjectDetector` и на основе обнаружений формирует команды движения через `/cmd_vel`.

### Получаемые данные

Контроллер подписывается на:

```text
/aliengo/base_velocity
/aliengo/joint_states
/aliengo/imu
/aliengo/camera/color/image_raw
/aliengo/camera/depth/image_raw
```

Команды движения публикуются в:

```text
/cmd_vel
```

### EXPLORING

Робот движется по полигону и одновременно ищет текущую цель.

Для обхода препятствий используется Depth-камера. Изображение разбивается на три горизонтальных сектора:

```text
┌──────────┬──────────┬──────────┐
│   LEFT   │  CENTER  │  RIGHT   │
└──────────┴──────────┴──────────┘
```

Если центральный сектор свободен, робот движется вперёд. Если впереди препятствие, выбирается направление с большей свободной дистанцией.

### APPROACHING

После обнаружения текущей цели робот начинает движение к ней.

Горизонтальное положение bounding box используется для определения направления поворота:

```text
объект левее центра  → поворот
объект по центру     → движение вперёд
объект правее центра → поворот
```

Скорость движения дополнительно зависит от расстояния до объекта.

### REACHED

После достижения объекта робот останавливается и остаётся в состоянии `REACHED` в течение `1.5` секунды.

Затем текущая цель считается пройденной и выбирается следующая.

### Последовательность объектов

По умолчанию робот должен найти объекты в следующем порядке:

```text
cup
laptop
bottle
chair
backpack
```

## `isaac_controller_log.py`

`isaac_controller_log.py` предназначен для запуска и логирования симуляции Isaac Gym.

В отличие от `controller.py`, который реализует высокоуровневую логику навигации через ROS 2, этот файл связывает симуляцию Aliengo с `SimBridgeClient` и обученной policy для управления походкой робота.

### Загрузка policy

Из каталога обученного запуска загружаются два TorchScript-модуля:

```text
body_latest.jit
adaptation_module_latest.jit
```

`adaptation_module` формирует latent representation из истории наблюдений, после чего `body` использует историю наблюдений и latent для формирования управляющего действия.

### Настройка симуляции

Файл восстанавливает параметры окружения из `parameters.pkl`, после чего настраивает одиночное окружение, terrain и фронтальную RGB-D камеру. В частности, задаются разрешения:

```text
RGB:   640 × 360
Depth: 848 × 480
```

Команды `vx`, `vy`, `wz` принимаются через `SimBridgeClient`, передаются в окружение Isaac Gym, а полученные сенсорные данные отправляются обратно через bridge.

### Логирование

Файл создаёт отдельный лог запуска, в котором сохраняются:

* seed;

* последовательность объектов;

* положения объектов на полигоне;

* время;

* координаты `x`, `y`;

* ориентация `yaw`;

* информация о найденных объектах.
